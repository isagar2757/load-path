Policy guards

Every tool call goes through guarded_call. The active document in MongoDB policies decides allow or deny.

← Control surface

How a call is judged

A call is (session, actor, tool, args). All checks on the active policy must pass.

  1. Load sessionMust be running; actor must be active
  2. Find policyOne active policy for this tool
  3. Run checksFirst failure becomes the deny reason
  4. Record + runDecision event, then execute only if allowed

Always deny when: no active policy, inactive actor, session not running, or any exception.

Allow when: every named check on the policy is true.

What each check means

Implemented in core/gate.py; names come from contracts.py.

  • role

    Actor’s roles must intersect the policy’s roles (e.g. only programming may commit_budget).

  • spend_limit

    args.amount must be ≤ the session human’s spend_limit (owner_a: 100M, engineer_b: 10k).

  • envelope

    Committed budget in the session plus this amount must stay within session.budget_envelope.

  • jurisdiction

    Asset region must match the session region; for a human actor, also match the actor’s region.

  • has_commitment

    A committed budget line must already exist for that asset in this session.

  • in_approved_plan

    The active plan must contain a line with the same asset and amount.

  • has_reason

    args.reason must be a non-empty string (used on reject).
